# Proposal templates / Шаблони відгуків

Use one template for a relevant task. Replace every bracketed item with a fact from the client's brief, and remove any sentence you cannot support. These are first-contact drafts; they are not reports of completed work.

## 1. Python bot fix

**EN**

Hi [name], I can investigate [specific failure] in your Python bot. From your description, the key check is [observable expected behaviour]. I would start with a reproducible example, trace the failing handler and check the focused fix against the same case and a repeated event. Could you share [sanitized traceback or small reproduction]? A related example of my work is the Transactional Review Workflow in my portfolio.

**UA**

Вітаю, [ім'я]. Можу дослідити [конкретний збій] у вашому Python-боті. З опису важливо перевірити [спостережувана очікувана поведінка]. Почну з відтворення проблеми, знайду причину в обробнику та перевірю зміну на початковому сценарії й повторній події. Чи можете надати [знеособлений traceback або приклад]? Схожа робота в портфоліо — Transactional Review Workflow.

## 2. API integration

**EN**

Hi [name], your task is to move [authorized data] from [API] into [application or database]. I can build that integration around the provider's documented limits and your required update behaviour. We can agree on checks for a normal response, a timeout and duplicate input. Please send the API documentation and a synthetic request/response example; production keys are not needed for the first discussion.

**UA**

Вітаю, [ім'я]. Вам потрібно передати [дозволені дані] з [API] до [застосунку або бази даних]. Можу реалізувати інтеграцію з урахуванням документації сервісу та потрібного оновлення даних. Погодимо перевірки звичайної відповіді, таймауту й повторного запису. Надішліть документацію API та тестовий приклад запиту й відповіді; робочі ключі для першого обговорення не потрібні.

## 3. Telegram workflow

**EN**

Hi [name], I can build the [request / review / support] workflow you described for your authorized users. The main steps appear to be [step A], [step B] and [step C], with [role] responsible for [decision]. I would confirm the status rules and repeated-click behaviour before implementation. My review-workflow case covers similar role and reservation logic. Please clarify [one missing business rule].

**UA**

Вітаю, [ім'я]. Можу створити описаний процес [заявок / погоджень / підтримки] у Telegram для ваших уповноважених користувачів. Основні кроки: [крок A], [крок B] і [крок C]; роль [роль] відповідає за [рішення]. Перед реалізацією погодимо переходи станів і поведінку повторного натискання. Схожа логіка є в моєму кейсі перевірки заявок. Уточніть, будь ласка, [одне невідоме бізнес-правило].

## 4. Internal web dashboard

**EN**

Hi [name], I can create a focused internal dashboard for [operators] to [main action]. I would keep the first scope to [screens and actions] and connect it to [existing backend/data source]. Acceptance can cover role access, status updates and the empty/error states you need. My web operations and local dashboard cases show related work. Do you already have an API contract or a synthetic data sample?

**UA**

Вітаю, [ім'я]. Можу створити внутрішню панель, щоб [оператори] могли [основна дія]. Перший обсяг пропоную обмежити [екрани й дії] та підключити до [наявний backend або джерело даних]. Для приймання погодимо доступ ролей, оновлення станів і потрібні порожні та помилкові стани. У портфоліо є схожі вебпанелі. Чи маєте контракт API або тестовий набір даних?

## 5. Automation and debugging

**EN**

Hi [name], I can help trace why [job or integration] [repeats / stalls / loses state]. I would first identify where the expected state diverges from the recorded result, then propose a narrow fix with a regression check. If a remote action times out, we should distinguish a known failure from an unknown result before retrying. Could you share a sanitized event timeline and the expected final state?

**UA**

Вітаю, [ім'я]. Допоможу з'ясувати, чому [задача або інтеграція] [повторюється / зависає / втрачає стан]. Спочатку визначу, де очікуваний стан розходиться із записаним результатом, потім запропоную конкретне виправлення та регресійну перевірку. Якщо зовнішня дія завершилась таймаутом, перед повтором потрібно розрізнити відому відмову й невідомий результат. Чи можете надати знеособлену послідовність подій та очікуваний кінцевий стан?
